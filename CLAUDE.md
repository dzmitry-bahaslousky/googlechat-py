# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

An unofficial async Python client for Google Chat's **private web API** (the one chat.google.com itself uses), plus two thin front-ends over it: the `gchat` CLI and the `googlechat-mcp` MCP server. Auth is the user's own browser cookies — no Google Cloud project or OAuth. The protocol is reverse-engineered (from EionRobb/purple-googlechat) and can break whenever Google changes it.

## Commands

```bash
uv sync                                   # install deps (incl. dev group)
uv run pytest                             # all tests, offline
uv run pytest tests/test_api.py::test_name -q   # one test
uv run python -m tests.record_fixtures    # re-record live fixtures (needs `googlechat-mcp login`; read-only calls)
uv run gchat --json spaces                # run the CLI from the checkout
uv run googlechat-mcp                     # run the MCP server (stdio)
```

There is no linter/formatter configured. `src/googlechat/_proto/googlechat_pb2.py` is generated by protoc for protobuf 6.31.1 from `googlechat.proto` (it validates the runtime version on import) — don't hand-edit it; regenerate after changing the `.proto`.

## Architecture

Layering (everything goes through the library; CLI and MCP add no protocol logic):

- `client.GoogleChatClient` — builds one `Transport` and exposes sub-APIs: `spaces`, `members` (`_spaces.py`), `messages` (`_messages.py`), `reactions`, `users`. `from_storage()` loads cookies from the config dir and writes rotated cookies back.
- `_transport.Transport` — the only place that does HTTP:
  1. `GET /mole/world` → parse `WIZ_global_data.SMqcke` as the XSRF token (`auth.parse_xsrf_token`), cached and lock-guarded. On a 400, `post` refetches the token and resends once (any method: a refused request was not run); a signed-out `/mole/world` or a 401 raises `SessionExpiredError`.
  2. `POST /api/<method>?rt=b&alt=proto` with a binary protobuf body and header `X-Framework-XSRF-Token`.
  3. Every request gets a **WEB client `RequestHeader`** with a hand-encoded capability list (`_WEB_CAPABILITY_BYTES`); the web client type returns more naming data than iOS. Declaring a capability list disables any field left out, so send all of them.
  4. Cookies Google rotates (SIDCC etc.) are diffed after each response and passed to `on_cookies_changed` (saved atomically, mode 0600, by `auth.save_cookie_updates`).
- **Retry policy is safety-critical.** Only methods in `READ_METHODS` and `DEDUPED_WRITES` are retried (429/502/503/504, network errors, honouring `Retry-After`, max 30 s). Sends (`create_topic`, `create_message`) carry a unique client `local_id`; a 409 on a retry means an earlier attempt already posted (`SentMessage.already_posted`). A request that gets no answer raises `NetworkError`. Edits, deletes, reactions are never retried. When adding a new API method, put it in `READ_METHODS` only if it truly cannot change state.
- `_convert.py` — proto ↔ dataclass conversion (`types.py`). Spaces vs DMs use different `GroupId` shapes, so calls take `space_id` + optional `is_dm`; when it is `None`, `SpacesAPI.resolve` looks the id up in the chat list (cached per client, filled by every listing).
- `serialize.py` — compact JSON shared by CLI `--json` and MCP tool output.
- `login.py` — Playwright drives real Chrome with a dedicated profile under the config dir; tries a silent headless refresh before opening a window.
- `mcp_server.py` — FastMCP tools over a lazily created module-level client; on `SessionExpiredError` it drops the client so the next call reloads cookies from disk (calls still running on it finish first; its later cookie updates are discarded). Write tools (`WRITE_TOOLS`) are registered only with `GCHAT_MCP_WRITE=1`, because text the read tools return is written by other people and could steer the agent. Put any new state-changing tool in `WRITE_TOOLS`.
- `cli.py` — click; commands that post as the user (`send`, `reply`, `edit`, `delete`, `react`, `dm`) require confirmation (edit and delete prompts show the message, fetched first) and refuse non-interactive use without `--yes`. Keep write operations behind that guard.

Names follow Google's official Chat API (space, thread, message, member) even though the wire protocol uses group/topic.

## Tests

- `tests/conftest.py` provides `FakeChat`: a fake chat.google.com behind `httpx.MockTransport`. It decodes each request by method (`REQUEST_TYPES` — add new API methods there), records calls, serves canned replies, and can force statuses/queues for retry tests. Its default `paginated_world` reply lists the ids tests use (spaces S1, S2, S7–S9; DMs D1, D9) so calls without `is_dm` resolve. `client._transport._sleep` is swapped so retries don't actually wait. pytest runs with `asyncio_mode = "auto"`.
- `tests/fixtures/live/` holds real recorded responses with every string scrubbed to a same-shaped fake (`tests/scrub.py`); `test_recorded.py` replays them, matching requests with `request_header` cleared. Operations to record are listed in `tests/recorded_ops.py`. The recorder refuses to write if any original value survives scrubbing — never commit unscrubbed responses.

## Config

`GCHAT_CONFIG_DIR` (default `~/.config/googlechat-mcp`), `GCHAT_COOKIES`, `GCHAT_PROFILE`, `GCHAT_MCP_WRITE`. Required cookies: `SID`, `SAPISID`, `__Secure-1PSID`.
